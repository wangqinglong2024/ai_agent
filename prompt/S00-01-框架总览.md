# 02 · G01 · 框架总览

> 本文件回答三个问题：本框架是什么、为什么这样设计、怎么使用。

---

## 一、是什么

一套从「业务诉求」到「上线增长」全链路的标准化提示词模板集，覆盖 12 个阶段、12 种角色、约 40 份模板。

它不替你写代码，它让 AI 在每一步都按你定义的格式做事，并在所有不清楚的地方主动问你，直到产出可以被下游机械消费的文档。

---

## 二、为什么这样设计

AI 协同开发最常见的三个翻车点：

1. **AI 凭空脑补**：用户没说的细节，AI 直接默认了，下游全错。
2. **上下文塞太多**：一次喂 1 万字，AI 抓不住重点，丢字段。
3. **角色串场**：让"画原型的 AI"同时定数据库字段，结果两头不到位。

本框架的三个解药：

| 解药 | 落地形态 |
|------|---------|
| 强制澄清协议 | 每一步必经"用户填表 → AI 必先提问 → 用户答 → AI 出报告"，AI 跳步即打回 |
| 上下文最小化 | 每一步明确"系统消息只塞这几份文件"，禁止全塞 |
| 角色独立窗口 | 12 阶段 × 不同角色，独立对话窗口，互不污染 |

## 三、12 阶段执行顺序与依据

| 顺序 | 阶段 | 性质 | 为什么这个时机 |
|------|------|------|--------------|
| 1 | R 需求分析 | 一次性 | 万事之始，把"模糊的话"变成结构化需求清单 + 流程图 |
| 2 | A 技术架构 | 一次性 | 选栈、定目录、定数据库/接口/编码规范——后续所有产物都按它走 |
| 3 | P 权限与角色 | 一次性 | 角色枚举要先定，所有功能的可见性、操作权限都要它 |
| 4 | D 数据模型 | **按功能循环** | **先于交互**：数据结构是地基，没数据谈不了接口和页面 |
| 5 | L 业务与接口 | **按功能循环** | 数据有了，定义对它能做什么操作 |
| 6 | X 体验定调（UX 调性）| 一次性 · **可跳过** | **先于视觉**：决定"产品给人的感觉"；沿用 `design/01-experience/` 则跳过三件套 |
| 7 | S 设计系统 | 一次性 · **可跳过** | 把 X 的调性落成 Token、组件、布局；沿用 `design/02-design-system/` 则跳过三件套 |
| 8 | I 信息架构 | 一次性 | 路由结构、页面清单、导航结构，全局骨架 |
| 9 | N 页面交互 | **按页面循环** | 数据/接口/视觉/IA 全到位，才能精准描述每个页面的行为 |
| 10 | H HTML 原型 | **按模块循环** | 原型不是"瞎画"，而是把前面所有规范"活"出来：可点通、有真数据型态、有调性 |
| 11 | E 产品需求文档（PRD）| 一次性汇总 | 基于已有原型 + 上游 10 阶段冻结产物，撰写一份「任何人接手即可读懂」的总章 PRD |
| 12 | V 开发前一致性校验 | 一次性 · 最终闸门 | V01 全局上游链 + V02 各模块内闭环 + V03 PRD 回链；三颗全 ✅ 才进开发 |

> **一次性 vs 循环口诀**：上下两头是一次性的全局产物（架构/权限/体验/设计/IA 在前，PRD/校验 在后）；中间的 D/L/N/H 是按模块一趟走完再起下一模块，也可多模块并行。
> **跳过机制**：项目不需重出 UX/视觉时，直接复制 `design/01-experience/*` → `docs/S06-ux/`、`design/02-design-system/*` → `docs/S07-design-system/`，即可省揉 S06、S07 三件套。

## 四、阶段角色

| 阶段 | 角色 | 单一职责 | 严禁做的事 |
|------|------|---------|-----------|
| R | 需求分析师 | 把模糊业务 → 结构化需求 + 流程图 | 不做技术选型、不画 UI |
| A | 架构师 | 选栈、定规范、定目录 | 不写功能字段、不写页面 |
| P | 安全/权限工程师 | 定角色、定认证、定授权 | 不实现具体业务接口 |
| D | 数据建模师 | 表结构、枚举、状态机、校验 | 不定接口、不定页面 |
| L | 接口设计师 | 接口契约、错误码、并发策略 | 不写 SQL、不写 UI |
| X | 体验总监 | 产品调性、参照、品牌情绪 | 不画具体组件 |
| S | UI 设计师 | Token、组件、布局、状态色 | 不定接口、不定页面交互 |
| I | 信息架构师 | 路由、页面清单、导航 | 不画单页布局 |
| N | 交互设计师 | 单页布局/元素/行为/4 态 | 不定接口、不写代码 |
| H | 原型工 | 出可点通 HTML | 不动业务规范 |
| E | 产品经理 | 复述并组织上游沉淀，输出多文件 PRD | 不新增需求、不改字段、不写代码、不引入新角色 |
| V | QA / 文档审计师 | V01 全局上游链 / V02 模块闭环 / V03 PRD 回链 三份报告 | 不写业务代码、不拆 Story、不打编码包 |

---

## 五、阶段闸门（Gate）

每阶段必经闸门才能进入下一阶段。任何 Gate 不通过 → 回到本阶段重做，**严禁强行往下推**。

| Gate | 通过判定 |
|------|---------|
| G-R | 需求基线无 `[待确认]`、覆盖主路径与异常路径、用户签字 |
| G-A | 架构规范无遗留问题、数据库/API/编码规范全部锁死 |
| G-P | 角色枚举与认证策略锁死，与 R 阶段角色清单一致 |
| G-D | 单功能数据规范字段齐全、状态机闭合、校验完整 |
| G-L | 单功能接口规范覆盖所有操作、错误码完备、与 D 字段一致 |
| G-X | 体验定调有 ≥3 个参照、有"反例"、有可验证的形容词 |
| G-S | 设计 Token 完备、所有组件都有 4 态、与 X 调性吻合 |
| G-I | 路由覆盖所有需求、每条需求都被某页承载 |
| G-N | 单页面规范元素齐全、4 态齐全、引用 D/L/S/P 全部对齐 |
| G-H | 原型可点通、4 态齐全、用户三轮内不再大改 |
| G-E | 17 份子文件全部产出；每句话可回链上游 ID；术语统一；范围声明三桶完整覆盖；99 节为空 |
| G-V | V01/V02/V03 三份报告皆无红色项；所有 99 节为空；取得后**才**进入开发 |

---

## 六、最小用法

```
建好 docs/ 目录 → 复制 S01-R01 填需求 → AI 出 S01-R02 提问 → 你答 → AI 出 S01-R03 基线 →
依次跑 A/P（一次性）→ 逐模块跑 D · L（多模块可并行）→
X/S（一次性；可直接复制 design/ 跳过）→ I（一次性）→
逐页跑 N → 逐模块出 H 原型，迭代稳定 →
E 起 PRD（三件套）→ V 跑 V01/V02/V03 三份校验 → 全绿 → 进入编码
```

每一步只做一件事，AI 只看当下需要的文件。
