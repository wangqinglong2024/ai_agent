2. **C/D 隔离铁律**：本阶段是产品设计阶段，**严禁**触碰任何后端实现细节——不读 docs/B01-architecture/、不假设接口签名、不假设数据库字段、不假设路由路径，也不向用户提问"这个调什么接口 / 字段叫什么 / URL 怎么写"。

4. 阻断级 ≤ 8、优化级 ≤ 15。

6. 即使 H01 看似零歧义，也必须显式输出本轮自检结论；无问题时输出"本轮无澄清问题，进入 C04-H03"。

## 必盘点的 14 维

### A. 与上游一致性
1. 本 feature N 规范里的 `page-id` / `Block-ID` 与本轮 H01 引用的是否一一对应？缺哪些？
2. 本 feature C02-IA `04-pages.md` 与本次要新增/改动的页面是否一致？是否需同步回写 04-pages.md（页面增删属于 C02 范畴）？
3. C02-IA `03-state-machines.md` 涉及的页面在原型里是否已表达不同状态下的差异？
4. B03 体验原则是否被违反（焦点态、动效时长、空状态文案语气）？
5. B04 设计系统：本次需要的 token / 组件是否已存在？若不存在，是补 token 还是绕开？

### B. 原型实现边界
6. 数据来源：用静态 mock？还是 `_mock/` 目录的某个 JSON？字段命名用业务语言（**禁用**数据库列名 / 后端字段名）。
7. 交互真实度：表单只做前端校验，还是要模拟提交 loading + toast？
8. 原型内跳转：以 `<page-id>.html` 命名 HTML 文件作锚；**不假设任何 URL 路径**（路由属于后续开发阶段）。
9. 可访问性：键盘可达、`aria-*`、`prefers-reduced-motion` 是否本轮纳入？
10. 状态四件套截图（默认/加载/空/错）是否本轮全出？
11. 移动端断点：375 / 768 / 1280 三档是否全做？

### C. 反馈条目歧义（仅迭代轮次需要）
12. F-<n>「<引用原文>」中的"期望"与现有 N 规范第 X 节是否冲突？以哪条为准？
13. 全局诉求「<引用原文>」会影响哪些未在反馈里点名的页面？是否一并改？
14. 反馈优先级"应改/可改"在本轮是否纳入？还是只做"必改"？
